# Systematic Debugging - 系統化除錯指南

本技能提供一套標準化流程，用於高效且系統地解決程式碼錯誤。

## 核心原則

1.  **重現問題 (Reproduce)**: 確保問題穩定重現，並記錄重現步驟。
2.  **隔離問題 (Isolate)**: 縮小問題範圍，排除無關代碼或環境因素。
3.  **日誌分析 (Analyze Logs)**: 仔細檢查錯誤訊息、堆疊追蹤 (stack traces) 和任何相關日誌輸出。
4.  **根因分析 (Root Cause Analysis - RCA)**: 找出導致問題的根本原因，而非僅修補表面現象。
5.  **修復與驗證 (Fix & Verify)**: 應用解決方案，並徹底測試以確保問題已解決且沒有引入新問題。

## 適用情境

- 功能不按預期運作。
- 程式碼崩潰或產生錯誤訊息。
- 不同環境（開發、測試、生產）之間行為不一致。
- 性能下降或資源洩漏。

## 步驟詳情

### 1. 重現問題 (Reproduce)

- **目標**: 找到最小化且穩定的重現步驟。
- **行動**:
  - 明確的輸入、執行路徑和預期輸出。
  - 如果無法穩定重現，則專注於收集更多資訊（日誌、環境變數）。

### 2. 隔離問題 (Isolate)

- **目標**: 找出問題代碼的最小集合。
- **行動**:
  - **二分法 (Binary Search)**: 逐步註釋或移除代碼塊，直到問題消失。
  - **變更控制 (Version Control)**: 使用 `git bisect` 查找引入錯誤的提交。
  - **最小化案例 (Minimal Test Case)**: 建立一個只包含問題相關代碼的獨立測試案例。

### 3. 日誌分析 (Analyze Logs)

- **目標**: 從現有資訊中提取線索。
- **行動**:
  - 檢查終端機輸出、瀏覽器控制台、伺服器日誌。
  - 理解錯誤類型（SyntaxError, TypeError, ReferenceError 等）。
  - 追蹤堆疊追蹤，定位到具體的檔案和行號。

### 4. 根因分析 (Root Cause Analysis - RCA)

- **目標**: 識別錯誤的根本原因。
- **行動**:
  - 基於隔離和日誌分析的結果，提出假設。
  - 使用除錯器 (Debugger) 逐步執行代碼，檢查變數狀態。
  - 查閱文件或外部資源，了解相關函式或 API 的行為。
  - 與團隊成員討論或尋求協助 (Peer Review)。

### 5. 修復與驗證 (Fix & Verify)

- **目標**: 解決問題並確保穩定性。
- **行動**:
  - 實施修正。
  - 編寫或運行測試案例，確認問題已解決。
  - 檢查是否有副作用或引入新錯誤。
  - 提交修正，並在提交訊息中簡要說明問題和解決方案。
